# Pi OpenTUI

A terminal UI for the Pi coding agent, built on OpenTUI + Solid. Work is planned in `.scratch/pi-opentui/` (spec and numbered tickets). Use the vocabulary in `GLOSSARY.md`. A bare "extension" means this project's Extension, so say "Pi extension" for Pi's.

## Rules that are easy to get wrong

- **Never write OpenTUI or Pi API calls from memory.** OpenTUI 0.8.x is young and changes fast, and Pi's RPC protocol is specific to each version. Check OpenTUI in Context7 (`/websites/opentui`) and Pi in the docs shipped in `node_modules/@earendil-works/pi-coding-agent/docs/` (`rpc.md`, `rpc-commands.md`, `rpc-extension-ui.md`, `json.md`, `keybindings.md`) against the installed version before using any API. Exact signatures for the installed version live in `node_modules`: Pi's protocol in `@earendil-works/pi-coding-agent/dist/modes/rpc/rpc-types.d.ts` and `dist/modes/json-event.d.ts`, Solid element props in `@opentui/solid/src/types/elements.d.ts`, renderable options in `@opentui/core/renderables/*.d.ts`, and the test renderer in `@opentui/core/testing/*.d.ts`. Runtime behaviour the `.d.ts` hides (setter validation, hit-testing) is in `@opentui/core/index.bun.js` and `chunk-bun-*.js`; grep there. Pi behaviour its docs omit (retries, refusing to compact, turns that end in an error) is in `@earendil-works/pi-coding-agent/dist/core/agent-session.js`, what new, switch and fork do is in `dist/core/agent-session-runtime.js`, when a session file is written is in `dist/core/session-manager.js` (format: `docs/session-format.md`), `@earendil-works/pi-ai/dist/utils/retry.js` and `pi-agent-core/dist/agent-loop.js`; `dist/bundle/` is minified, so never grep it.
- **Runtime is Bun.** OpenTUI needs Bun ≥ 1.3.14 or Node ≥ 26.4, and Node 24 can't run it. `pnpm check` runs tsc, Biome and `bun test`. Fix lint with `biome check --write .`, because `biome format` does not sort imports.
- **Solid typings under OpenTUI's JSX have two traps.** `<input onSubmit>` types its argument as `string | SubmitEvent`, so write a handler with no arguments that reads the value from a signal. The function child of `<Show when>` gets an implicit `any` parameter, so compute the value once and render `value && <…/>` instead.
- **OpenTUI silently drops style values its setter doesn't accept** (e.g. `flexBasis: "0%"` is ignored and stays `auto`), and props with no setter at all: Solid builds each element with only `{ id }` and then assigns props, so a constructor-only option such as `<markdown treeSitterClient>` never arrives. A layout probe can pass for the wrong reason. Stay within the typed props and test layouts with content in the Panels.
- **Modified keys need the kitty protocol in tests.** Without it a terminal sends Shift+Enter as plain Enter, so `startPiu` turns on `kittyKeyboard` (the real renderer does by default); Alt arrives as `meta`. `<textarea>`'s default bindings are the reverse of a chat prompt (Enter inserts a newline, Alt+Enter submits), so the prompt routes keys in `onKeyDown` and calls `event.preventDefault()` to skip them.
- **Global `useKeyboard` listeners run before the focused element's `onKeyDown`, and their `preventDefault` skips it.** The app's Tab and Shift+Tab handler would otherwise steal Tab from the prompt's autocomplete, so a Module that needs Tab calls `context.holdFocusKeys(active)`.
- **A Module that focuses itself on creation fires `focused_renderable` before Solid has attached it to its Panel**, so `src/focus.ts` re-checks which Panel holds the focus after the render pass. The focus indication is the Panel id in the border title, because `captureCharFrame` shows no colour and another `borderStyle` breaks `panelText`.
- **`// why:` comments about OpenTUI or Pi quirks are not limited to 1–2 per change.** The limit in the global instructions covers the rest.
- **An `<input>` in a row is only as wide as its text** (the placeholder counts), so typed text scrolls and the frame shows its tail. Give it `flexGrow={1}`.
- **A `<For>` item function runs untracked.** Pass `selected` to a helper as a getter (`() => at() === row()`), or the highlight never updates.
- **Biome's a11y rules are DOM-only.** When one fires on an OpenTUI element (`<box onMouseDown>`), turn that rule off in `biome.json` (`noStaticElementInteractions` already is) instead of suppressing it inline.
- **Pi is a subprocess over RPC, never in-process.** Don't call `createAgentSession` from the app (ADR-0001). Talk to it through the app's own Backend client, not Pi's `RpcClient`, which can only run `node <cli.js>` and copies the child's stderr to our terminal. Frame stdout as LF-only JSONL, never with `readline`, which splits on `U+2028/2029` inside JSON. Never write the Backend's stderr to the terminal. `@earendil-works/pi-coding-agent` is a dev dependency: import only its protocol types, plus the test binary.
- **Tests never touch the developer's Pi.** In the author's shell, `pi` is a function that runs Pi-Bolt under a sandbox. Tests run the pinned dev-dependency `pi` binary directly, with `PI_CODING_AGENT_DIR` set to a temp dir, `PI_OFFLINE=1` and `--no-session`, and the faux model from `@earendil-works/pi-ai`. `startPiu` also passes `--no-skills`, because Pi finds skills under the home folder regardless of `PI_CODING_AGENT_DIR`. A test that needs a saved session (Restart, `-c`) sets `persistSession` instead of `--no-session`; the temp agent dir still keeps it away from the real one.
- **Tests go through `startPiu`** (`test/harness.ts`), the seam spec.md already agreed, so use it without confirming a seam. A test that passes on its first run isn't done until you break the code under test on purpose and watch it go red; the Restart test once passed on stale state alone. Copy the file to the scratchpad before breaking it, because `git checkout` can't restore uncommitted work. A `waitForFrame` predicate waits for everything the test asserts next, or the first matching frame can be mid-render (`isFormatted` flaked this way). Before asserting that something is absent (`not.toContain`), wait for a frame that shows the Backend data it would come from has arrived, or the check passes before the data exists. An overlay such as the autocomplete list is drawn over Panel text, so assert on a whole line (`startsWith`), not `includes`. Run a new file of frame tests 10–15 times in a row before closing the ticket. `panelText(frame, column, row)` in the harness returns the text of the Panel that contains that column and row, so assert on one Panel instead of the whole frame. A timed-out `waitForFrame` prints the whole frame, so run tests through a filter, `bun test <file> 2>&1 | grep -a "^(fail)\| pass\| fail" | cut -c1-200`, and read a full frame only for the one failing test. `-t` takes a regex, so escape parentheses in a test name. `pnpm check` takes about a minute, so run it alone with a long `timeout`, not chained after other commands. When a spec story names several ways to do one thing (mouse or keyboard, default or given position), each way gets its own test.
- **Native frame stats can't see re-highlighting.** `getNativeStats().frameWork` misses JS and worker work. To bound streaming render cost, spy on `getTreeSitterClient().highlightOnce` (the singleton `CodeRenderable` uses by default) and bound what each call highlights. This is the agreed seam for render-cost tests.
- **Animation tests drive a `ManualClock`.** `startPiu` blanks `animations` to `false` unless the test's config says otherwise, so the regular suite never animates. A test that wants motion passes `animations: true` and `clock: new ManualClock()` (from `@opentui/core/testing`), then steps `clock.advance(20)` + `renderOnce()` and reads the frames; time never moves on its own. One big `advance` hands the whole delta to a timeline that a timer callback just created (the Toast's exit), so advance in small steps near a timer. Toast timeouts run on `renderer.clock` for the same reason. `captureCharFrame` has no colour, so the motions are slides and row reveals, never fades: assert on a text's row or column.
- **`translateX`/`translateY` are Renderable setters, not JSX props.** Set them from a `ref` plus a `createEffect`. A Module animates only through `context.animate`, never with its own timers; with `animations: false` it calls `onUpdate(to)` and `onComplete` synchronously, and a `loop` animation does nothing at all.
- **Smooth wheel scrolling sets the event's `scroll.delta` to 0** so the scrollbox's own step becomes a no-op that still counts as taking the event (`src/smooth-scroll.ts`). `preventDefault` does not stop that step, and `scrollOnce`'s chain bookkeeping is not exported in the types.
- **Scripted replies can be steps** (`FauxStep` in `test/harness.ts`: `thinking`, `text`, `toolCalls`, `error`). A step with tool calls needs another reply after it, because Pi calls the model again with the result. An `error` such as `529 overloaded` is retried, while `400 invalid request` is not. A compaction spends two scripted replies. Assert "running" with a slow `bash` command (`sleep 0.6`), since `read` finishes between frame polls.
- **`layout.test.ts` places the built-in `input.prompt` in a Panel of its own height.** When you change the prompt's height, or the default Layout's input sizes, update that test's Panel too. The default input Panel is sized to its content, so the prompt's fixed `height` on its textarea sets the Panel's 5 rows, and `ask-user.test.ts` asserts those rows.
- **A `"content"`-sized Panel is a plain bordered `<box>`, not a `<scrollbox>`.** A scrollbox's native viewport never shrinks to its content, so it grows to fill the space instead.
- **A Solid store array read as `store.list` tracks nothing in an effect.** Spread it (`[...store.list]`) so the effect reruns when entries are added or removed; the dialog bridge once showed no Modal for this reason.
- **Extension UI tests drive Pi through the `ui` tool** (`uiTool` in `FauxScript`). Its schema is a plain JSON object, because `typebox` is not a dependency here. `renderer.setTerminalTitle` throws `InvalidPhase` in the test renderer, so a test that spies on it mocks the implementation.
- **Fixture Extensions live under `test/fixtures/`, inside the repo.** A temp dir cannot resolve `solid-js`, `@opentui/solid` or the `tsconfig` JSX settings, so a `.tsx` fixture written there fails to import.
- **Bun's module cache is shared by every test in a file.** To assert that an Extension was or was not loaded, use a fixture that no other test places, or the result depends on test order.
- **A `<Portal>` is not a screen-sized overlay.** Its container is a plain box in the flow of `renderer.root`, below the app, so an absolute child is placed relative to a point off-screen. Make the container absolute at 0,0 through the Portal's `ref` (the prompt's autocomplete list does) and position children with `screenX`/`screenY`. A Portal does not take focus or keys, which is why the list is not a Modal (`ModalLayer` swallows keys outside the top Modal).
- **A textarea's `cursorOffset` counts display cells, not JS string indices** (a CJK character is 2, a newline 1). Read text before the cursor with `getTextRange(0, cursorOffset)`, and edit with `deleteCharBackward()`/`insertText()` instead of computing offsets. `captureCharFrame` also splits emoji, so test wide text with CJK.
- **Mouse-down focuses the clicked element after your handler runs** (`dispatchMouseEvent` in `chunk-bun-*.js`), which steals focus from whatever your handler just focused. A handler that opens or closes a Modal, or otherwise moves focus, calls `event.preventDefault()`.
- **Pi lists a model for every provider with credentials in the environment**, so the author's `OPENROUTER_API_KEY` put hundreds of real models in the picker. `startPiu` blanks env vars matching `API_KEY|_TOKEN|_SECRET` for the Backend; keep any new test launcher doing the same.
- **Config merge:** objects merge by key, while arrays and `layout` replace. A replaced `layout` drops the default Placement entries for Panels the new tree lacks, but a `placement` key you write for a missing Panel is a startup error.
- **A duplicate tool name is a hard startup failure on Pi-Bolt** (ADR-0001). An Extension's Pi extension never reuses another tool's name. To replace a tool, register your own name and drop the old one from `event.systemPromptOptions.selectedTools` in `before_agent_start`. `pi.setActiveTools()` does not hold, because the installed rpiv package re-adds its tool in a `before_agent_start` that runs after ours. A test stand-in for an installed Pi extension must copy behaviour like that (`test/fixtures/pi-extensions/`, placed with `installedPiExtensions`), or it passes on code that fails on the real one. Before writing a stand-in for an installed Pi extension, read the real one's hooks (`pi.on(...)`): the author's installed packages are in `~/.pi/agent/npm/node_modules/` (read-only). Check with `bun scripts/pi-bolt-compat/run.ts`, a manual script that needs your real agent dir: an empty one has no compiled-in Pi extensions. Run it as soon as the Pi extension first works, not at the end of the ticket.
- **An Extension's `commands` load only when one of its Modules is in the Placement.** `resolvePlacement` imports an Extension through its placed Modules, so a command-only Extension never reaches `/`. The session commands sit in `builtin/chat` for that reason.
- **The `/` list shows 8 rows and every app command is in it**, so a new command pushes entries out of view. Autocomplete tests type a narrowing query (`/re`) instead of a bare `/`, and a list row starts with the Panel border (`│ /name `), not with the name.
- **A new, resumed or forked Pi session re-runs the faux extension, so a test script's replies start again from the first.** Prove "fresh session" with `{messages}` or `{lastUser}`, not with reply order. Pi's RPC cannot branch inside one session, so `branchBackCommand` navigates the tree from a fixture command.
- **The default Backend in `config.ts` stays `pi`.** Personal settings such as `pi-bolt` go in `config.json`, which is git-ignored, as is the `extensions/` folder except its README. Never commit either.

## Agent skills

### Issue tracker

Issues and specs live as local markdown files under `.scratch/<feature>/`. Before committing a finished ticket, close it: tick its checkboxes, set `Status: done`, and record every deviation from the ticket under `## Comments`. A leftover that a later ticket owns also goes into that ticket as a `From NN:` comment, or its agent never sees it. See `docs/agents/issue-tracker.md`.

### Triage labels

Default five-role vocabulary, recorded as a `Status:` line in each issue file. See `docs/agents/triage-labels.md`.

### Domain docs

Single-context: `GLOSSARY.md` and `docs/adr/` at the repo root. See `docs/agents/domain.md`.
