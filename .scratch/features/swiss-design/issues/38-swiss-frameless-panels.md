# 38: Swiss: Panels без рамок, разделители и фокус

**What to build:** Panels больше не рисуются рамками `┌─┐`. Экран белый, Panels отделены только линиями: над областью ввода жирная чёрная `━`, между остальными соседними Panels тонкая линия цвета `border`. Panel без видимых Modules (по умолчанию боковая `side`) не показывается вовсе. Фокус показывается без рамки.

**Blocked by:** 37 (токены `signal`, `faint`).

**Status:** done

## Решения

- **Рамка Panel → разделитель.** `paintCard` для Panels (`src/layout.tsx`) больше не рисует контур. В колонке Panel, у которой есть сосед сверху, рисует горизонтальную линию по своей верхней строке (механизм `joinAbove` и общая строка остаются). В ряду Panel, у которой есть сосед слева, рисует вертикальную линию по своей левой колонке. Внешних краёв у экрана нет.
- **Линия над областью ввода** (Container `input-area`, `joinAbove`) жирная `━` цвета `text`. Остальные разделители тонкие `─`/`│` цвета `border`. Где задаётся «жирная» (поле Slot или правило для `input-area`), решить в плане. Если это новое поле Slot, его надо внести в `slotKeys` (`src/config.ts`).
- **Отступы сохраняются**, чтобы геометрия содержимого не менялась: строка разделителя остаётся зарезервированной, левая пустая колонка остаётся.
- **Фокус (согласовано с пользователем):** у Panel в фокусе, кроме Panel с полем ввода, в верхней строке слева её имя (`title` или `id`) красным (`signal`) жирным. Фокус на поле ввода видно по красным `›` и курсору (тикет 40); без фокуса они `faint`. Пока тикет 40 не сделан, у поля ввода в фокусе курсор просто красный.
- **Пустая Panel скрыта** при любом `size`, не только `"content"`: `visible` учитывает `entries.some(shown)`. Её место отдаётся соседям.
- **Modal** остаётся плоским прямоугольником без контура, как сейчас. Его вид меняет тикет 42.
- **Тесты находят Panels по раскладке, а не по символам рамки.** Хелперы `panelText`, `inputTop`, `inputArea`, `statusArea`, `focusedPanels`, `besidePanels`, `panelTitle` в `test/harness.ts` переписываются: границы Panel берутся из её renderable (`screenX/screenY/width/height`), например по `id`, который `SlotView` даёт коробке Panel. API поиска renderable по id проверить в `@opentui/core`. Сигнатуры хелперов по возможности не меняются: около 250 вызовов в тестах должны остаться как есть. Таблица `glyphs` сжимается до того, что ещё рисуется.

## Критерии приёмки

- [x] Ни одна Panel не рисует `┌ ┐ └ ┘`; над областью ввода жирная линия `━` на всю ширину основной колонки.
- [x] Две Panels рядом разделены одной тонкой вертикальной линией, две Panels друг над другом одной тонкой горизонтальной.

## Comments

- Жирная линия задаётся не новым полем Slot, а существующим `joinAbove`: строку, которую Container делит со Slot сверху, первая видимая Panel рисует как `━` цвета `text`. `slotKeys` не менялся.
- «Сосед сверху/слева» определяется геометрически: Panel рисует верхнюю линию, если её `screenY > 0`, и левую, если `screenX > 0` (`paintPanel` в `src/card.ts`). На стыке вертикальной и горизонтальной линий стоит `─`, без `┬`/`┼`.
- Когда видна `status`, жирная линия идёт над ней, а между `status` и полем ввода тонкая `─` (по правилу «остальные разделители тонкие»). В макете строки статуса нет; если её там не должно быть, это решать в 39/40.
- Пустые Panels внутри Modal не скрываются: Modal по тикету не меняется, а скрытый Modal держал бы клавиши.
- Сигнатуры хелперов: `inputTop(frame)` стал `inputTop()`; `panelTitle` и `besidePanels` удалены, их места переписаны на `focusedPanels` и `panelBoxes(piu)`. Хелперы, которые принимают только кадр, берут раскладку приложения, запущенного тестом последним. Добавлены `panelBoxes` и `sidePlacement`.
- `side` по умолчанию теперь скрыта, поэтому тесты, которым нужна вторая колонка, ставят туда `model.current`.
- Курсор поля ввода стал `signal`, курсор поиска моделей остался `text`; тест темы переписан под это.
- Падения, которые были до тикета (есть и на HEAD d50347b): два теста `/tree`, «the idle composer shows command and file hints followed by its directory», «the input Panel fits the card and restores the editor and directory after».
