# 37: Swiss: светлая палитра, подсветка кода и inline-код

**What to build:** Светлая тема получает палитру Swiss из макета `mockup/swiss-light.png`: белый фон, чёрный текст, красный только для того, что происходит прямо сейчас. Блоки кода в ответах подсвечиваются несколькими цветами. Inline-код из одинарных обратных кавычек рисуется синим на светлой подложке и отличается от жирного `**…**`. Раскладка и рамки в этом тикете не меняются (они в 38).

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

## Решения

- **Новые токены Theme:** `signal` (живое: идущий инструмент, курсор, `›`, working, маркеры списков), `faint` (подсказки, комментарии, длительности), `code` (синеватая подложка inline-кода), `codeBlock` (нейтральная подложка блока кода), `tertiary` (типы и атрибуты в коде). Токены публичные: Extensions читают их, Config может их заменить. Поэтому они идут в `themeTokens` (`src/theme.ts`), и их получает и тёмная тема. Её значения до тикета 43 временные, но читаемые.
- **Светлые значения** (из `mockup/swiss-light.js`):

  | Токен | Цвет | Где |
  | --- | --- | --- |
  | `background`, `surface` | `#ffffff` | фон всего экрана и Panels |
  | `raised` | `#f2f2f2` | сообщение пользователя, раскрытые тела Thinking и инструментов |
  | `text` | `#000000` | текст, ключевые слова кода (жирные), чипы инструментов (фон) |
  | `muted` | `#555555` | второстепенный текст |
  | `faint` | `#9a9a9a` | подсказки, комментарии, «you», длительности |
  | `border` | `#e3e3e3` | тонкие разделители |
  | `accent` | `#000000` | заголовки и выделенные элементы: Swiss держит акцент в чёрном |
  | `signal` | `#e10600` | всё живое и маркеры списков |
  | `secondary` | `#0040c1` | функции и теги в коде, inline-код, ссылки, `PickerLink` |
  | `tertiary` | `#7a1fa2` | типы и атрибуты в коде |
  | `success` | `#007a3d` | строки в коде, успешные service rows |
  | `warning` | `#b85400` | числа и константы в коде, предупреждения |
  | `error` | `#e10600` | ошибки |
  | `code` | `#f1f3f8` | синеватая подложка inline-кода |
  | `codeBlock` | `#f5f5f5` | нейтральная подложка блока кода |
  | `selection` | `#ebebeb` | выделенная строка |

- **Подсветка** (`createSyntaxStyle` в `builtin/chat/markdown.tsx`): `keyword` → `text` жирный; `function` → `secondary`; `type`, атрибуты/свойства → `tertiary`; `string` → `success`; `number`, `constant` → `warning`; `comment` → `faint` курсив; `operator`, `punctuation` → `muted`. Какие имена групп (`tag`, `attribute`, `property`, `variable.member` …) реально приходят из tree-sitter для ts/tsx, проверить по установленному `@opentui/core` (его highlight-запросы), не по памяти.
- **Markdown:** `markup.raw` (inline-код) → fg `secondary`, bg `code`, не жирный (`StyleDefinition` поддерживает `bg`). `markup.strong` остаётся жирным текстом цвета `text`. `markup.heading` → `text` жирный. `markup.list` → `signal`. `markup.link` → `secondary` с подчёркиванием.
- **Подложка блока кода:** `MarkdownRenderable` создаёт `CodeRenderable` с тем же `bg`, что у всего markdown (`createCodeRenderable` в `@opentui/core/index.bun.js`), поэтому отдельного фона у блока кода нет. Попробовать дать блоку кода фон `codeBlock` и отступ в одну колонку так, чтобы не сломать инкрементальную подсветку (тикет 06: законченные блоки не перерисовываются, `renderNode` создаёт и выбрасывает renderable на каждое обновление). Если чисто не выходит, блок кода остаётся без подложки, и это записывается в Comments. Хак, который перехватывает внутренние объекты markdown, не делать.

## Критерии приёмки

- [ ] На светлом терминале фон экрана белый, текст чёрный, цвета токенов совпадают с таблицей.
- [ ] Блок кода в ответе подсвечен: ключевые слова, функции, типы, строки, числа и комментарии различаются по цвету или начертанию.
- [ ] Inline-код синий на подложке `code` и не жирный; `**…**` жирный чёрный без подложки.
- [ ] Маркеры списков красные, заголовки чёрные жирные.
- [ ] Новые токены можно заменить в Config (`theme.signal` и т. д.), неизвестный токен остаётся ошибкой запуска.
- [ ] Тёмная тема получает значения новых токенов и остаётся читаемой (её дизайн в тикете 43).

### Проверки

- [ ] Через `startPiu` с `terminalBackground: "light"`: ответ со списком, `**жирным**`, inline-кодом и блоком ts-кода; цвета и фон проверяются по `captureSpans` (подсветка ждёт highlight, см. существующий тест про keyword в `test/theme.test.ts`).
- [ ] Проверка Config: замена `signal` применяется, токен `nope` даёт ошибку с путём.
- [ ] Мутационная проверка каждого нового теста.
