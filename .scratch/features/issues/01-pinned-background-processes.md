# 01: Закреплять выполняющиеся неблокирующие процессы внизу чата

**What to build:** Выполняющиеся неблокирующие фоновые процессы видны в закреплённой области внизу agent Panel, над областью ввода. Новые сообщения и ручная прокрутка истории вверх не скрывают эту область. После завершения процесса закрепление снимается, а его карточка с итоговым статусом остаётся в истории чата.

**Blocked by:** None (can start immediately).

**Status:** done

## Критерии приёмки

- [x] Процесс, запущенный в фоне установленным Pi extension `@pify/shell-background`, появляется в закреплённой области с идентификатором задания, командой и статусом выполнения.
- [x] Поддерживаются как явный запуск `bash` в фоне, так и автоматический перевод долгого foreground-запуска в фон. Обычный блокирующий вызов инструмента сам по себе не считается неблокирующим процессом.
- [x] Новые сообщения пользователя, потоковый ответ ассистента и результаты других инструментов не вытесняют выполняющийся процесс из закреплённой области.
- [x] При ручной прокрутке истории вверх процессы остаются видимыми внизу agent Panel. Их обновления не возвращают историю к последнему сообщению и не забирают клавиатурный фокус у поля ввода.
- [x] Несколько фоновых процессов представлены отдельно; завершение одного снимает закрепление только с него. Идентичные команды с разными идентификаторами заданий не сливаются.
- [x] Завершение запускающего вызова `bash` и завершение хода агента не снимают закрепление с продолжающего работать процесса.
- [x] После фактического завершения, ошибки или подтверждённой остановки процесса закрепление снимается без нового сообщения пользователя и без необходимости просить модель вызвать `shell_status`. Работает и завершение во время другого активного хода агента.
- [x] После снятия закрепления в истории остаётся одна карточка процесса с его итоговым статусом; повторные сведения от `shell_status`, `shell_kill` или сообщения о завершении не создают дубликатов карточки процесса.
- [x] Если выполняющихся процессов нет, закреплённая область не занимает места. Переход в другую сессию не переносит в неё процессы предыдущей.
- [x] Закрепление остаётся частью чата при его переносе через Placement или замене Layout, не требует второй колонки и не закрывает поле ввода. Без установленного shell-background приложение продолжает работать как прежде.
- [x] Проверки через кадры приложения покрывают явный и автоматический фон, несколько процессов, появление новых сообщений, ручную прокрутку вверх и снятие закрепления с сохранением итоговой карточки. Стенд воспроизводит существенное поведение установленного Pi extension, но не запускает личный Pi и его реальные задания.

## Comments

- Пользователь подтвердил: закрепление сохраняется при ручной прокрутке истории; после завершения процесса карточка остаётся в истории без закрепления.
- При подготовке тикета изучен установленный `@pify/shell-background` 0.7.0. Он возвращает идентификатор задания и состояние процесса в метаданных результата инструмента; результат запуска в фоне сообщает о ещё работающем задании. Полученный `toolResult` не означает, что процесс завершился.
- Штатный виджет этого Pi extension создаётся фабрикой для Pi TUI. Установленный RPC Backend игнорирует такие фабрики, поэтому одного отображения `setWidget` недостаточно. Нужен источник фактического состояния заданий, работающий через существующую границу Backend и без дополнительных ходов модели. Способ получения состояния выбирается при реализации; установленный пакет и личные настройки пользователя не изменяются.
- Автоматическое сообщение о результате имеет тип `pify-shell-background-result`. Оно может откладываться до завершения текущего хода, а автоматическая доставка результатов может быть отключена. Нельзя полагаться только на это сообщение для своевременного снятия закрепления. Обновлять по нему карточку задания допустимо; общий рендеринг сообщений типа custom в этот тикет не входит.
- Тикет не добавляет браузер заданий, кнопки управления процессами или панель во второй колонке. Исправление видимости ожидающих пользовательских сообщений не является его блокером.
- Решение пользователя: закрепление живёт в новой Panel `pinned` (content-размера) между `agent` и `input-area` в Layout по умолчанию; Module `background.processes` стоит в её Placement. Panel не занимает места, пока выполняющихся процессов нет. Вариант с нижней частью внутри agent Panel (флаг Module и правка `SlotView`) отклонён как более рискованный.
- Следствие: пункт про перенос через Placement выполнен (Module можно поставить в любую Panel, проверено на `side`). При замене Layout без Panel `pinned` Module не стоит в Placement, поэтому Extension не включается: закрепления нет, а карточка `bash` показывает `bg-N background` вместо статуса задания.
- Источник состояния: Pi extension `builtin/background/pi-extension.ts` узнаёт запуск из `tool_result` с `details.background === true` и каждые 250 мс читает sidecar `<tmpdir>/pify-shell-bg/<id сессии>/<задание>.json` внутри Backend. Снимок уходит через `setStatus` под зарезервированным ключом и разбирается один раз в `PiState.backgroundJobs`. Это связь с внутренним форматом `@pify/shell-background` 0.7.0; установленный пакет не менялся. Одних `tool_result`, `shell_status` и сообщения `pify-shell-background-result` недостаточно: сообщение откладывается до конца хода и может быть выключено.
- Карточка процесса: это карточка запускающего `bash`. Её статус берётся из задания по `details.id` (`running`, `done`, `failed`, `killed`) с префиксом идентификатора, а длительность запуска не показывается. Без сведений о задании (история старой сессии, нет Extension) статус `background`. Вызовы `shell_status` и `shell_kill` остаются обычными карточками инструментов, карточку процесса они не создают.
- Не в тикете, но добавлено: в закреплённой области не больше 5 строк, остальные сводятся к `+N more`.
- Не проверено: `scripts/pi-bolt-compat/run.ts` падает в песочнице (`EACCES` на `~/.pi/agent/trust.json.lock`), поэтому Pi extension на Pi-Bolt не пробовался. Запустить вручную до использования.
- Тесты: `test/background.test.ts` (13 кадровых тестов) со стендом `test/fixtures/pi-extensions/shell-background.ts`, который повторяет sidecar для каждого задания (в том числе foreground), `details.background`, отложенную доставку и убийство заданий при конце сессии.
- Известное ограничение: при `/reload` настоящий пакет передаёт задания новому экземпляру и не убивает их, а наш `session_shutdown` сбрасывает закрепление (RPC-режим `/reload` не использует). Отдельного состояния `maxBackground` и `stoppedByUser` стенд не повторяет. Проверка «ввод остаётся у поля» в тесте прокрутки слабая: перенаправление набора вернуло бы текст в поле и без фокуса.
