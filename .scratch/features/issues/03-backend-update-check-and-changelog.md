# 03: Проверять обновления Backend и показывать changelog при запуске

**What to build:** При запуске piu проверяет обновления только настроенного Backend — stock Pi или Pi-Bolt — и сообщает о доступной версии. После установки новой версии при следующем запуске открывается Modal с её changelog, в том числе при продолжении сохранённой беседы. Сама проверка ничего не устанавливает и не мешает работе приложения.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

## Критерии приёмки

- [ ] Проверка запускается асинхронно при старте: пользователь может вводить сообщения и работать с интерфейсом, не ожидая сети. Она не скачивает установщик и не меняет установленную версию.
- [ ] Определяются семейство, текущая версия и конкретная установка настроенного Backend. Проверка не подменяет выбранный Pi-Bolt установленным рядом Pi, другой копией из PATH или версией dev dependency приложения.
- [ ] Для Pi и Pi-Bolt используются соответствующие официальные источники релизов. Версия Pi-Bolt сравнивается с релизами Pi-Bolt, а не с номером включённого в него upstream Pi.
- [ ] При доступном обновлении видны имя Backend, текущая и доступная версии и подсказка `/update`. При актуальной версии сообщение об обновлении не появляется. Ошибка сети, таймаут или offline-режим не блокирует запуск и не выдаётся за успешную проверку.
- [ ] Проверка не зависит от способа установки: обязательные сценарии — curl-установщик, npm, pnpm и bun для обоих Backend. Наличие нескольких менеджеров пакетов само по себе не меняет определённую установку.
- [ ] После фактического перехода на новую версию Modal показывает changelog выбранного Backend за обновлённые версии. Если пропущено несколько релизов, видны изменения между предыдущей известной и новой установленной версиями, а не только последнего релиза.
- [ ] Modal открывается и после обычного запуска, и при продолжении сессии после перезапуска. Она поддерживает Markdown, независимую прокрутку мышью и клавиатурой, стандартное закрытие и удержание фокуса.
- [ ] Сведения о предыдущей версии и просмотренном changelog сохраняются между процессами отдельно для разных установок Backend. Закрытый changelog не появляется при каждом следующем запуске той же версии; обновление одного Backend не помечает просмотренными изменения другого.
- [ ] Недоступный changelog не подменяется выдуманным текстом или changelog другого продукта: видны фактическая версия и понятное сообщение со ссылкой на официальный источник. Установка не считается успешной только из-за наличия заметок о релизе.
- [ ] Изолированные проверки покрывают оба семейства Backend, выбор правильной установки, доступное и отсутствующее обновление, сетевую ошибку, смену версии между двумя запусками, Modal в продолженной сессии и отсутствие повторного показа после закрытия. Используются управляемые ответы источников релизов; реальные глобальные установки не обновляются.

## Comments

- Этот тикет самостоятельно проверяется сменой версии тестовой установки между запусками. Автоматическая установка и перезапуск после `/update` относятся к следующему тикету, поэтому команды перезапуска не являются блокером здесь.
- У stock Pi 1.5.0 проверка версии и автоматический changelog реализованы в его интерактивном интерфейсе, а changelog пропускается при продолжении сессии. Нельзя рассчитывать, что RPC Backend сам покажет требуемую Modal в piu.
- У Pi-Bolt есть собственная версия дистрибутива и отдельная версия включённого Pi. Источником версии не должен служить только package metadata upstream Pi или сохранённый манифест старой компиляции.
- Состояние показа хранится со стороны piu, без изменения личной истории просмотра changelog в обычном Pi. Отслеживание версии позволяет показать изменения и после обновления, выполненного вне piu.
- На следующем тикете используются определённая установка Backend, сведения о версиях и механизм показа changelog из этого тикета.
