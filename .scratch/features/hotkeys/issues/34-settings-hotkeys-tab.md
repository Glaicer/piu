# 34: Вкладка «Hotkeys» в Settings

**What to build:** В Modal «Settings» появляется вкладка «Hotkeys». В ней видны все действия, на которые можно назначить клавиши, включая действия Extensions, и их сочетания. Здесь же сочетание можно добавить, убрать или сбросить к умолчанию. Конфликты видны: какое действие какое сочетание потеряло и кому. Изменения сразу действуют и записываются в личный Config.

**Blocked by:** 32 (Modal «Settings» с вкладками и вкладка Global), 33 (действия Extensions, несколько сочетаний и последовательности в keybindings).

**Status:** done

## Решения

- **Вкладка встроенная** и добавлена тем же механизмом вкладок, что Global. Порядок: Global, Extensions (тикет 29), Hotkeys. Если 29 ещё не сделан, Hotkeys идёт сразу после Global.
- **Действия сгруппированы по источнику:** piu и каждая загруженная Extension. Действия незагруженных Extensions не показываются.
- **Изменения применяются сразу**, без черновика, как в Global (тикет 32), и пишутся тем же способом записи личного Config в `keybindings.<action>`. Одно сочетание записывается строкой, несколько — массивом, снятые все — `[]`. Сброс к умолчанию удаляет ключ, а не записывает умолчание.
- **Запись нового сочетания:** после «добавить» piu ловит следующие нажатия. Сочетание закончено после второго нажатия или после паузы в 1 секунду после первого: это правило ожидания из тикета 33. Esc отменяет запись, поэтому назначить Esc через вкладку нельзя, только в Config.
- **Конфликт не мешает назначению:** по правилу тикета 33 новое назначение позже и побеждает. До подтверждения вкладка говорит, у какого действия сочетание будет отнято.

## Критерии приёмки

- [x] Вкладка показывает каждое действие с описанием, всеми его сочетаниями и пометкой, изменены ли они относительно умолчания.
- [x] Действие Extension (например, Alt+M у `modes` из тикета 24) видно в группе своей Extension и меняется так же, как встроенное.
- [x] Сочетание, которое действие потеряло из-за конфликта, отмечено, и видно, какое действие его забрало.
- [x] Добавить сочетание: одиночное и последовательность из двух нажатий; Esc отменяет запись.
- [x] Перед назначением занятого сочетания вкладка показывает, у какого действия оно будет отнято; отказ ничего не меняет.
- [x] Убрать одно сочетание, убрать все (`[]`), сбросить к умолчанию (ключ удалён из личного Config).
- [x] Изменение действует сразу, без Restart, и сохраняется после Restart; остальные ключи личного Config не меняются.
- [x] Во время записи сочетания нажатия не запускают действия и не попадают в input.
- [x] Назначение `shift+return` (отдельно или нажатием последовательности) любому действию, кроме `input.newline`, не сохраняется: вкладка показывает ошибку, личный Config не меняется. Shift+Enter у `input.newline` показан как неизменяемый, убрать его нельзя.
- [x] Список прокручивается, если не помещается.

## Comments

**From 33:** `ResolvedKeybindings` in `src/keybindings.ts` exposes `actions` (id, description, source, defaults), `requested`, `effective`, `conflicts` (`loser`/`winner`) and `overridden` (the action ids present in the personal Config). `ModuleContext.keybindings` is now `Accessor<ResolvedKeybindings>`, and `prepareKeybindings` in `src/app.tsx` builds it once at startup; live writes and reactive Config changes are still this ticket's work.

Выполнено 2026-11-18 от базы `8cf2400`.

- Вкладка встроенная, порядок: Global, Hotkeys, затем вкладки Extensions (тикет 29 ещё не сделан). Список — строки действий; `↑/↓` выбирают действие, `←/→` сочетание, `⏎` начинает запись, `⌫/Del` убирает выбранное, `c` пишет `[]`, `r` удаляет ключ, Home/End и колесо прокручивают. Статус ошибки и предупреждения о конфликте вынесен в футер модала, вне scrollbox, поэтому виден и для действий ниже первого экрана.
- В `src/app.tsx` личный слой и разрешённые сочетания стали Solid-сигналами; `resolveKeybindings` пересчитывается при каждом изменении. Поэтому маршрутизатор, подсказка новой строки и подсказка `chat.bottom` меняются без Restart.
- `saveKeybinding` перечитывает Config и меняет только `keybindings.<action>`: одно сочетание — строка, несколько — массив, снятые все — `[]`, сброс — удаление ключа. Новое назначение переносит ключ действия в конец, потому что порядок ключей решает конфликт; удаление и `[]` сохраняют место, сброс удаляет. Правило записано в ADR-0002.
- Запись нового сочетания использует `sequenceTimeoutMs` (1 с) на `renderer.clock`. Shift+Enter и Ctrl+C решаются сразу после первого нажатия, потому что не могут начинать последовательность. Esc поглощается `ModalLayer` и отменяет запись через `onDismiss`; Settings остаётся открытым. Это же описано в `docs/agents/opentui.md`.
- Shift+Enter у `input.newline` всегда показан чипом `⇧⏎ fixed` и исключён из редактируемого списка, поэтому убрать его нельзя и когда он записан в Config. Одиночный Shift+Enter для `input.newline` вкладка не записывает и показывает сообщение, хотя Config это значение по-прежнему принимает (правило тикета 33). Для остальных действий Shift+Enter отклоняется так же, как в Config.
- Маркер `changed` сравнивает действующий список с умолчаниями по значениям, а не по наличию личного ключа: личный ключ, равный умолчанию, не помечается.
- Клавиша `+` (и `ctrl++`) не записывается в Config, потому что `parseChord` её не разбирает; вкладка показывает ошибку вместо сохранения невалидного ключа.
- Если запись не удалась (например, Config стал невалидным JSON), изменение остаётся в памяти, а Toast сообщает об ошибке — как у Global по ADR-0002.

Все тесты используют временный `PIU_HOME`.
