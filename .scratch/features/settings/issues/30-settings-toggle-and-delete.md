# 30: Включение, выключение и удаление extensions в Settings

**What to build:** Во вкладке «Extensions» у каждой строки галочка «вкл/выкл» и действие «удалить». Изменения копятся в черновике и записываются только по «Сохранить»; закрытие с несохранёнными изменениями спрашивает, отбросить ли их. Удаление перед записью подтверждается списком того, что будет удалено. После записи тикет 31 применяет изменения; до него piu говорит, что изменения вступят в силу после Restart.

**Blocked by:** 29 (`/settings` и Modal «Settings» со списком extensions).

**Status:** ready-for-agent

## Решения

- **Выключение Extension — отдельная секция Config, а не правка Placement.** `"extensions": { "<name>": { "enabled": false } }`. Нет ключа — Extension включена; включение удаляет ключ, а не пишет `true`. Объект, а не список: объекты в Config сливаются по ключам, а массивы заменяются, так что список в личном Config молча отменил бы чужие записи. Объект оставляет место для других полей Extension.
- **Placement не трогается.** Модули выключенной Extension исчезают из своих Panels, но их записи в Placement остаются, поэтому повторное включение возвращает их на прежние места. Будущая смена позиции из Settings правит только Placement, и две вещи не мешают друг другу.
- **Выключенная Extension выключена целиком:** её Modules не рисуются, её команд нет в `/`, её Pi extension не передаётся Backend (`-e`), её Extension channels не резервируются.
- **Ссылки на выключенную Extension не ошибка.** Запись Placement, `modules.<id>` и keybinding её команды просто не действуют. Ссылка на несуществующую Extension и неизвестное имя в секции `extensions` остаются ошибками запуска, как вся строгость Config.
- **`chat` и `input` выключить и удалить нельзя.** Без них пользователь не наберёт `/settings`, чтобы вернуть их. В строке вместо галочки — пояснение.
- **Удалить можно только своё.** Agentic: файл Pi extension (файл удаляется, его запись в Pi settings тоже) и пакет (через `<backend> remove <source>`, где `<backend>` — настроенный `backend.command`). Interface: личная Extension из `PIU_HOME`. Её папка удаляется вместе со всеми ссылками на неё в личном Config: ключ в секции `extensions`, её Modules в `placement`, `modules.<id>` и keybindings её команд. Иначе ссылка на несуществующую Extension сломает следующий запуск. Встроенные в Pi-Bolt и в piu можно только выключить.
- **Extension, найденная, но не размещённая** (ни один её Module не стоит в Placement), и так не загружается. Строка показывает это («не размещена»), галочка у неё работает как у любой, но без размещения ничего не меняет. Размещение из Settings — будущая работа вместе со сменой позиции.
- **Agentic пишется в Pi settings Backend'а** в тех формах, которые описывает документация Pi: `-<path>` в `extensions` для файла, фильтр `"extensions": []` в записи пакета, механизм `pi config` для встроенных. Piu впервые пишет файл Pi: записать это в ADR о записи настроек, заведённый в тикете 32. Pi сам пишет этот файл во время работы (например, `lastChangelogVersion`), поэтому запись — прочитать, изменить, записать атомарно непосредственно перед применением; проверить, есть ли у Pi блокировка settings, и уважать её.
- **Interface пишется в личный Config** (`PIU_HOME/config.json`), с сохранением всех остальных ключей. Запись личного Config уже есть с тикета 32: переиспользовать её и дополнить её ADR записью в Pi settings.

## Критерии приёмки

- [ ] Галочка переключает строку в черновике; изменённые строки отмечены до сохранения.
- [ ] «Сохранить» записывает изменения: Agentic — в Pi settings, Interface — в личный Config. Без изменений «Сохранить» ничего не пишет.
- [ ] Закрытие Modal с несохранёнными изменениями спрашивает подтверждение; отказ оставляет Modal открытым.
- [ ] «Удалить» помечает строку; при сохранении piu показывает список удаляемого и удаляет только после подтверждения.
- [ ] После Restart выключенная Extension не видна, её команд нет в `/`, её Pi extension не загружен; после повторного включения и Restart её Modules стоят на прежних местах.
- [ ] Config с `"extensions": { "<name>": { "enabled": false } }` разбирается; `"extensions"` добавлен в список допустимых ключей Config; неизвестное имя или неизвестное поле — ошибка запуска с путём.
- [ ] После сохранения Pi settings остаются валидными и содержат все ключи, что были до записи.

### Проверки

- [ ] Проверки разбора Config для новой секции: выключение, отсутствие ключа, неизвестное имя, неизвестное поле, слияние личного Config с умолчанием.
- [ ] Проверка через `startPiu` с временным `PIU_HOME`: выключить Extension, сохранить, перезапустить — Module пропал; включить, сохранить, перезапустить — Module на прежнем месте.
- [ ] Проверка с временным agent dir: выключение файла Pi extension записывает `-<path>`, включение убирает запись; другие ключи Pi settings не изменились.
- [ ] Проверка: удаление личной Extension и файла Pi extension после подтверждения; отказ ничего не удаляет.
- [ ] Проверка: личная Extension с Module в личном `placement` и keybinding её команды удаляется, и следующий запуск проходит без ошибки Config.
- [ ] Тесты не трогают настоящий agent dir, `~/.piu` и не запускают настоящий `remove`.
