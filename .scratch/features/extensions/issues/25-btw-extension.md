# 25: `/btw` — побочный вопрос в отдельном окне

**What to build:** Extension `btw` с Pi extension внутри. `/btw <вопрос>` открывает Modal и сразу задаёт вопрос модели о текущей сессии; `/btw` без текста открывает Modal с пустым полем ввода. Ответ стримится в окно, в том же окне можно задавать следующие вопросы — они продолжают ту же побочную ветку. Ничего из этого не попадает в контекст сессии.

Личный Pi extension `btw` делает это через `ctx.ui.custom()`, а в RPC это no-op, поэтому под piu `/btw` сейчас не работает. Его ценная часть — Pi-сторона: он оборачивает `streamSimple` провайдера и запоминает последний запрос основного диалога, поэтому побочный вопрос попадает в кэш промпта. Эта часть переносится в Pi extension Extension'а без изменения поведения, окно делается заново как Modal.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

## Критерии приёмки

- [ ] Побочный вопрос отправляется с тем же префиксом, что последний запрос основного диалога (модель, сообщения, опции), плюс сообщения побочной ветки; tools и `tool_choice` такие же, как в основном запросе. Без записанного запроса (сразу после resume) префикс собирается из ветки сессии, как сейчас.
- [ ] Ответ стримится в Modal по мере прихода текста.
- [ ] Esc во время ответа прерывает его; Esc без активного ответа закрывает Modal. Закрытие Modal во время ответа прерывает запрос.
- [ ] Окно прокручивается стрелками и PageUp/PageDown; при новом тексте окно держится у конца, если пользователь не прокрутил вверх.
- [ ] Ни вопрос, ни ответ не появляются в сессии, в её файле и в следующих запросах основного диалога.
- [ ] Побочная ветка забывается при смене сессии, переходе по дереву и компакции.
- [ ] Без выбранной модели или при ошибке провайдера окно показывает понятную ошибку, а не пустоту.

### Проверки

- [ ] Проверка через `startPiu` с faux model: `/btw вопрос` открывает Modal, ответ faux model появляется в нём; после закрытия список сообщений сессии не изменился.
- [ ] Проверка: второй вопрос в том же окне отправляется с первым вопросом и ответом в истории.
- [ ] Проверка: Esc посреди медленного стрима прерывает ответ, Modal остаётся открытым; второй Esc закрывает его.

## Notes

- Extension channel начинает Pi extension (Dialog `editor`) и устроен как запрос-ответ, а стриминг идёт в одну сторону много раз. Как передавать поток (зарезервированные ключи `setStatus`, как у логов субагентов, или иначе) — решить в плане тикета.
- Прочитать `docs/agents/pi-extensions.md` до начала.
- Extension загружает свои `commands` и Pi extension, только если один из её Modules стоит в Placement по умолчанию. Значит, Extension нужен размещённый Module, хотя бы скрытый (`reportPresence("hidden")`), или общий prefactor, который снимает это ограничение (не заведён).
- Исходник для справки: `btw.ts` в agent dir (выключен в Pi settings).

## После приёмки (вручную)

- [ ] Удалить `btw.ts` из agent dir и его строку `-extensions/btw.ts` из Pi settings.
