# 28: Окно фоновых задач

**What to build:** Modal со списком фоновых задач `@pify/shell-background` текущей сессии: команда, статус и время работы каждой задачи. Выбранная задача показывает хвост своего лога, обновляющийся, пока она работает, и её можно остановить. Modal открывается командой piu и кликом по задаче в пине фоновых задач (сразу на этой задаче).

Сам tool и управление процессами остаются в пакете. Под piu его браузер задач недоступен: это оверлей Pi TUI, а `/shell-bg status` и `list` в RPC отдают текст через `notify`, то есть в Toast, где лог не прочитать.

**Blocked by:** None (can start immediately). Пакет `@pify/shell-background` снова включён в Pi settings и вкомпилирован в Pi-Bolt (2026-11-13).

**Status:** ready-for-agent

## Критерии приёмки

- [ ] Modal показывает все задачи сессии, которые знает пин, в том же порядке и с теми же статусами.
- [ ] Выбранная задача показывает последние строки своего лога; пока задача работает, хвост обновляется; если лог недоступен, это сказано явно.
- [ ] Остановка выбранной работающей задачи останавливает её процесс и дерево процессов так же, как `/shell-bg kill <id>`; статус в Modal и пине меняется. Для завершённой задачи остановка недоступна.
- [ ] Клик по задаче в пине открывает Modal на этой задаче.
- [ ] Имя команды piu не совпадает с `/shell-bg` пакета.
- [ ] Modal закрывается Esc и кликом вне него.

### Проверки

- [ ] Проверка через `startPiu` со stand-in `shell-background`: две задачи, Modal показывает обе; выбор показывает строки лога задачи.
- [ ] Проверка: остановка работающей задачи меняет её статус в Modal и в пине.
- [ ] Stand-in пишет лог по пути, который записан в sidecar, как настоящий пакет; если stand-in этого не делает, его надо дополнить по исходнику пакета.

## Notes

- Sidecar задачи — это весь объект задачи пакета в JSON, включая путь к логу. Формат скопирован из версии 0.7.0: при обновлении пакета перечитать его исходники (реестр, kill, tail) в установленном пакете.
- Как остановить задачу из piu (команда пакета через RPC или свой путь) — решить в плане тикета; убийство процессов не дублировать, если пакет это уже умеет.
- Команда и Modal живут во встроенной Extension `background`: её Module `background.processes` уже стоит в Placement по умолчанию, поэтому её команды загружаются. Без пина в Placement не будет и команды — так же, как сейчас без пина нет статуса задач.
- Прочитать `docs/agents/pi-extensions.md` и раздел `docs/agents/testing.md` про stand-in `shell-background` до начала.
