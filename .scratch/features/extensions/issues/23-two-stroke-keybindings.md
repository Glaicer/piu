# 23: Двухклавишные сочетания в Keybindings

**What to build:** В Config можно назначить действию последовательность из двух нажатий, например `"command.model": "ctrl+x m"` и `"command.reasoning": "ctrl+x t"`. После первого нажатия piu ждёт второе; если оно совпало, выполняется действие, а набранный текст в input не меняется. Это нативная замена Pi extension `selector-chords` (Ctrl+X M открывал выбор модели, Ctrl+X T — уровень thinking), которая под piu не работает: она подменяет editor component.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

## Критерии приёмки

- [ ] Значение keybinding может быть одним сочетанием (как сейчас) или двумя, разделёнными пробелом. Каждое из двух разбирается по тем же правилам, что одиночное; неверная запись — ошибка запуска с путём `keybindings.<action>`, как сейчас.
- [ ] После первого нажатия последовательности piu ждёт второе не дольше 1 секунды. Совпавшее второе нажатие выполняет действие и не попадает в input.
- [ ] Esc во время ожидания отменяет последовательность и больше ничего не делает.
- [ ] Несовпавшее второе нажатие или истёкшее ожидание отдают оба нажатия дальше по обычному пути, как если бы последовательности не было: текст и другие сочетания работают как раньше.
- [ ] Две последовательности с общим первым нажатием (`ctrl+x m` и `ctrl+x t`) работают обе.
- [ ] Одиночное сочетание, совпадающее с первым нажатием какой-то последовательности, — ошибка запуска: иначе одно из них никогда не сработает.
- [ ] Значения по умолчанию в репозитории не меняются.

### Проверки

- [ ] Проверка через `startPiu` с Config `"command.model": "ctrl+x m"` нажимает Ctrl+X, затем M и подтверждает, что открылся выбор модели, а текст в input не изменился.
- [ ] Проверка нажимает Ctrl+X, затем букву, не входящую в последовательность, и подтверждает обычную обработку обоих нажатий.
- [ ] Проверка нажимает Ctrl+X и Esc: ничего не открылось, input не изменился.
- [ ] Проверки разбора Config: последовательность из двух сочетаний принимается, из трёх и с неверной частью — ошибка, конфликт префикса — ошибка.
- [ ] Существующие проверки Keybindings продолжают проходить.

## Notes

- Действие сейчас хранит одно сочетание, поэтому `ctrl+x m` заменяет `ctrl+l` для `command.model`, а не добавляется к нему. Несколько сочетаний на одно действие в тикет не входят.
- Никто не проверял, что input делает с Ctrl+X сейчас (например, вырезание). Проверка конфликтов в Config этого не увидит: проверить и решить в плане тикета, кто получает Ctrl+X первым.
- Исходник Pi extension для справки: `selector-chords.ts` в agent dir (выключен в Pi settings).
