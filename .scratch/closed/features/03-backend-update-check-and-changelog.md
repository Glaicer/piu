# 03: Проверять обновления Backend и показывать changelog при запуске

**What to build:** При запуске piu проверяет обновления только настроенного Backend — stock Pi или Pi-Bolt — и сообщает о доступной версии. После установки новой версии при следующем запуске открывается Modal с её changelog, в том числе при продолжении сохранённой беседы. Сама проверка ничего не устанавливает и не мешает работе приложения.

**Blocked by:** None (can start immediately).

**Status:** done

## Критерии приёмки

- [x] Проверка запускается асинхронно при старте: пользователь может вводить сообщения и работать с интерфейсом, не ожидая сети. Она не скачивает установщик и не меняет установленную версию.
- [x] Определяются семейство, текущая версия и конкретная установка настроенного Backend. Проверка не подменяет выбранный Pi-Bolt установленным рядом Pi, другой копией из PATH или версией dev dependency приложения.
- [x] Для Pi и Pi-Bolt используются соответствующие официальные источники релизов. Версия Pi-Bolt сравнивается с релизами Pi-Bolt, а не с номером включённого в него upstream Pi.
- [x] При доступном обновлении видны имя Backend, текущая и доступная версии и подсказка `/update`. При актуальной версии сообщение об обновлении не появляется. Ошибка сети, таймаут или offline-режим не блокирует запуск и не выдаётся за успешную проверку.
- [x] Проверка не зависит от способа установки: обязательные сценарии — curl-установщик, npm, pnpm и bun для обоих Backend. Наличие нескольких менеджеров пакетов само по себе не меняет определённую установку.
- [x] После фактического перехода на новую версию Modal показывает changelog выбранного Backend за обновлённые версии. Если пропущено несколько релизов, видны изменения между предыдущей известной и новой установленной версиями, а не только последнего релиза.
- [x] Modal открывается и после обычного запуска, и при продолжении сессии после перезапуска. Она поддерживает Markdown, независимую прокрутку мышью и клавиатурой, стандартное закрытие и удержание фокуса.
- [x] Сведения о предыдущей версии и просмотренном changelog сохраняются между процессами отдельно для разных установок Backend. Закрытый changelog не появляется при каждом следующем запуске той же версии; обновление одного Backend не помечает просмотренными изменения другого.
- [x] Недоступный changelog не подменяется выдуманным текстом или changelog другого продукта: видны фактическая версия и понятное сообщение со ссылкой на официальный источник. Установка не считается успешной только из-за наличия заметок о релизе.
- [x] Изолированные проверки покрывают оба семейства Backend, выбор правильной установки, доступное и отсутствующее обновление, сетевую ошибку, смену версии между двумя запусками, Modal в продолженной сессии и отсутствие повторного показа после закрытия. Используются управляемые ответы источников релизов; реальные глобальные установки не обновляются.

## Comments

- Этот тикет самостоятельно проверяется сменой версии тестовой установки между запусками. Автоматическая установка и перезапуск после `/update` относятся к следующему тикету, поэтому команды перезапуска не являются блокером здесь.
- У stock Pi 1.5.0 проверка версии и автоматический changelog реализованы в его интерактивном интерфейсе, а changelog пропускается при продолжении сессии. Нельзя рассчитывать, что RPC Backend сам покажет требуемую Modal в piu.
- У Pi-Bolt есть собственная версия дистрибутива и отдельная версия включённого Pi. Источником версии не должен служить только package metadata upstream Pi или сохранённый манифест старой компиляции.
- Состояние показа хранится со стороны piu, без изменения личной истории просмотра changelog в обычном Pi. Отслеживание версии позволяет показать изменения и после обновления, выполненного вне piu.
- На следующем тикете используются определённая установка Backend, сведения о версиях и механизм показа changelog из этого тикета.
- Конфигурируемый Backend определяется запуском `backend.command` с `backend.args` и `--version` (`src/backend-install.ts`); идентификатор установки — семейство плюс realpath команды. Pi печатает `1.5.0`, Pi-Bolt — `1.5.2 (Pi-Bolt 1.2.1, …)`, берётся номер после `Pi-Bolt`. Команда, не печатающая версию Pi (обёртка вроде `bwrap`, чужая программа), не проверяется и ничего не показывает.
- Источники: stock Pi — `https://pi.dev/api/latest-version` для проверки и GitHub releases `earendil-works/pi` (теги `v*`) для changelog; Pi-Bolt — GitHub releases `opensec-git/Pi-Bolt` (теги `bolt-v*`) для обеих целей. Сверено живыми запросами. Запрашиваются последние 30 релизов; если пропущено больше, показываются только найденные.
- Отклонение/решение: уведомление об обновлении — Toast на 12 с (а не постоянный элемент), потому что он работает при любой раскладке Layout. `PI_OFFLINE` и `PI_SKIP_VERSION_CHECK` в окружении piu отключают оба сетевых запроса (changelog тогда показывается как недоступный, со ссылкой).
- Состояние хранится в `$PIU_HOME/backend-versions.json` (id установки → последняя известная версия), пишется атомарно. Первый запуск и понижение версии Modal не открывают, а запоминают версию. Версия записывается, когда Modal закрыт (Esc или клик снаружи); недоступный changelog тоже считается просмотренным после закрытия, иначе ошибка повторялась бы при каждом запуске.
- Не проверено: раскладки npm/pnpm/bun для Pi-Bolt в тестах — стенды с угаданным именем пакета (`pi-bolt`); проверка от раскладки не зависит, так как смотрит только на вывод `--version`. Процессного теста нет: перезапуск относится к тикету 02.
- Для тикета 04: `detectInstall` в `src/backend-install.ts` отдаёт `{ family, version, id }`, `releaseSource` в `src/releases.ts` — `latest` и `notes`, `createVersionStore` в `src/backend-versions.ts` — просмотренные версии, `changelogModal` в `src/changelog.tsx` — Modal. Способ установки (curl/npm/pnpm/bun) здесь не определяется, это задача 04.
