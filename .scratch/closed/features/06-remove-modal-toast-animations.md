# 06: Убрать анимации появления и закрытия Modal и Toast

**What to build:** Modal и Toast появляются сразу в конечном положении и исчезают без переходов. Анимации их появления и закрытия удаляются полностью, в том числе при `animations: true`. Остальные анимации интерфейса и время показа Toast не меняются.

**Blocked by:** None (can start immediately).

**Status:** done

## Критерии приёмки

- [x] Любая Modal, включая встроенные picker, changelog и Dialog от Pi extension, появляется в заданном положении и размере на первом кадре после открытия. Нет выезда, затухания, промежуточных положений или ожидания окончания перехода перед взаимодействием.
- [x] Modal исчезает на первом кадре после закрытия через Esc, клик снаружи, выбор или программное закрытие. Фокус возвращается сразу; закрытая Modal не остаётся нарисованной поверх уже доступного интерфейса. Стек Modal, удержание фокуса и обработка отмены Dialog сохраняют прежнее поведение.
- [x] Toast сразу отображается целиком на своём обычном месте, без анимации появления. По истечении существующего таймаута он исчезает без анимации закрытия и дополнительной задержки. Сообщения, виды Toast, одновременный показ нескольких Toast и отсутствие захвата фокуса не меняются.
- [x] Поведение одинаково при `animations: true` и `animations: false`, без новой настройки для возврата этих переходов. Глобальное отключение всех анимаций не используется как замена удалению анимаций Modal и Toast.
- [x] Из путей открытия и закрытия Modal и Toast удалены анимационные задачи, смещения и ожидание animation completion. Таймер времени показа Toast и его cleanup сохранены. Общий механизм `animate`, индикатор работы, раскрытие карточек и thinking-блоков, плавная прокрутка не отключаются.
- [x] Проверки через `startPiu` с обоими значениями `animations` подтверждают конечное положение на первом кадре без продвижения анимационных часов. Для Modal отдельно проверяются Esc, клик снаружи и закрытие после выбора, а также немедленный возврат ввода в prompt и корректное закрытие верхней Modal в стеке.
- [x] Проверки Toast на управляемых часах подтверждают полную видимость сразу, сохранение до истечения таймаута и отсутствие на первом кадре после него без дополнительного шага для анимации. Существующие тесты выезда Modal и Toast заменены проверками нового поведения; проверки остальных анимаций продолжают проходить.

## Comments

- Причина запроса: пользователю не нравится внешний вид переходов Modal и Toast, и он отмечает, что они тормозят. Это тикет на удаление переходов, а не на подбор другой анимации или её ускорение. Отдельный замер производительности при заведении тикета не проводился.
- Сейчас переходы реализованы в `src/modal.tsx` и `src/toast.tsx` через `animate` и смещения; тесты в `test/animation.test.ts` требуют промежуточных кадров. Эти ожидания заменяются только для Modal и Toast.
- Требование заменяет прежнюю user story 89 в spec. Анимации содержимого внутри Modal, например прокрутка, этим тикетом не меняются.
- Полный `pnpm check`: 335 тестов прошли, тест автоматической компактизации в `test/polish.test.ts` падает и на исходном HEAD с `No more faux responses queued`.
- Программное закрытие отдельно на первом кадре не проверено: выбор picker использует тот же возвращённый `close`, а существующие тесты покрывают остальные сценарии. Размер и заданное положение проверены на вложенной Modal, а не отдельно для каждого типа Modal.
