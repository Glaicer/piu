# 02: Команды полного перезапуска и выхода из piu

**What to build:** Команда `/restart` корректно завершает текущие Backend и piu, затем запускает оба заново с продолжением текущей сохранённой сессии. Команды `/q`, `/quit` и `/exit` — равнозначные способы корректно закрыть Backend и piu и вернуться в терминал, как при выходе из Pi. Действие касается только инстанса, в котором введена команда; остальные продолжают работать.

**Blocked by:** None (can start immediately).

**Status:** done

## Критерии приёмки

- [x] `/restart`, `/q`, `/quit` и `/exit` доступны в slash-автодополнении и выполняются при отправке через поле ввода.
- [x] Это локальные команды piu: они не отправляются модели как prompt, steering или follow-up и не попадают в историю беседы как пользовательские сообщения.
- [x] Каждая из команд выхода корректно завершает Backend и piu с успешным кодом выхода. Терминал возвращается в обычный режим ввода, курсор виден, обработка мыши и клавиатурные режимы приложения отключены.
- [x] При выходе Backend получает возможность штатного завершения и cleanup Pi extensions. Не остаётся старого Backend или принадлежащих ему управляемых дочерних процессов; сохранённая история беседы не удаляется.
- [x] При нескольких одновременно запущенных инстансах `/q`, `/quit`, `/exit` и `/restart` затрагивают только инициировавший инстанс, его Backend и принадлежащие им процессы. Остальные инстансы, включая запущенные в той же директории с той же personal Config, продолжают текущую работу и принимают новые сообщения.
- [x] `/restart` запускает новый процесс piu и новый Backend, а не только пересоздаёт интерфейс или повторно подключается к старому Backend. Перед передачей терминала новому запуску старый интерфейс корректно освобождает его.
- [x] После `/restart` продолжается именно сессия, активная в момент команды, в том числе после её смены через New, Resume или Fork. Видна сохранённая беседа, и новый prompt продолжает её без повторной отправки предыдущего сообщения модели.
- [x] Перезапуск сохраняет рабочую директорию, окружение, выбор personal Config и остальные стартовые параметры, не позволяя исходному выбору сессии подменить текущую. Config и Extensions загружаются заново обычным путём запуска.
- [x] Пустая, ещё не сохранённая сессия не подменяется последней посторонней сессией. Явный режим без сохранения сессии остаётся таким и после перезапуска; принудительное сохранение истории для него не добавляется.
- [x] Команды работают и во время работы агента, не ожидая окончания генерации или блокирующего инструмента. При завершении останавливается активная работа, а после перезапуска она не запускается повторно автоматически. Команды выхода и перезапуска также доступны при уже завершившемся Backend.
- [x] Повторный вызов команды во время завершения не создаёт несколько новых piu или Backend. Ошибка нового запуска видна как читаемая ошибка старта, а терминал не остаётся в сломанном режиме.
- [x] Существующая кнопка Restart на карточке сбоя продолжает восстанавливать только Backend. Полный `/restart` доступен и без предварительного сбоя и не подменяется этой кнопкой.
- [x] Проверки покрывают каждый из трёх алиасов выхода отдельно, локальную обработку во время активной работы и полный перезапуск с продолжением выбранной сессии. Проверяется фактическое завершение или замена процессов, а не только исчезновение текста из кадра; процесс piu в тесте отделён от процесса тестового раннера. Backend и сессии изолированы от личного Pi пользователя.
- [x] Процессные проверки с двумя одновременно работающими инстансами подтверждают для каждого алиаса выхода и для `/restart`, что соседний инстанс не завершается и его активная задача не отменяется. После команды соседний инстанс успешно продолжает разговор.

## Comments

- Уточнение пользователя: закрытие одного инстанса не должно закрывать другие. Cleanup ограничивается процессами, которыми владеет этот инстанс; глобальное завершение по имени программы или общей группе процессов не подходит. Это же ограничение действует при полном перезапуске.
- Для `/restart` принято продолжение текущей сохранённой сессии, как при существующем восстановлении Backend. Новый сеанс разговора создаётся через `/new`, а не через перезапуск приложения.
- В режиме без сохранения сессии перезапуск имеет те же ограничения, что ручной выход и повторный запуск: несохранённая беседа не переносится. Режим не должен молча превращаться в сохраняющий историю.
- В установленном stock Pi 1.5.0 документирован `/quit`; интерактивный обработчик выполняет штатное завершение приложения, освобождает терминал и вызывает cleanup runtime. Имена `/q` и `/exit` добавляются как запрошенные пользователем алиасы piu независимо от набора команд Backend.
- Сейчас кнопка Restart обслуживает только упавший Backend; полного перезапуска piu и локальных команд выхода нет. Отправка встроенной команды Pi как RPC prompt не заменяет завершение самого piu.
- Реальный выход и новый запуск нельзя доказать одним in-process тестовым renderer: нужен узкий процессный сценарий через публичный запуск приложения с контролируемым терминалом и изолированной конфигурацией. Завершать процесс тестового раннера или заменять проверку пустым кадром нельзя.
- Тикет не зависит от отображения сабагентов или закрепления фоновых процессов. Он не добавляет автообновление, установку новой версии, hot reload или сохранение несохранённых черновиков.

### Реализация (отклонения и решения)

- Полный перезапуск не может заменить процесс, который шелл считает foreground-задачей, поэтому `bin/piu.ts` стал тонким лаунчером, а приложение переехало в `bin/piu-app.ts`. Приложение записывает новые аргументы в файл из `PIU_HANDOFF`, выходит с кодом 75, лаунчер запускает новое приложение с тем же терминалом. Старое приложение и его Backend к этому моменту завершены. Лаунчер пробрасывает SIGTERM/SIGHUP приложению; любой другой код выхода возвращает как есть. Каждый запуск piu теперь — два процесса bun (лаунчер почти ничего не держит в памяти).
- Перезапуск использует `--session <текущий файл>` вместо `-c`: так пустая несохранённая сессия остаётся пустой (Pi сохраняет явный путь), а сессия соседнего инстанса не подхватывается. Текущий файл спрашивается у живого Backend через `get_state` (таймаут 2 с), у мёртвого берётся последний известный. Исходные `-c`, `-r`, `--session`, `--fork`, `--session-id` из командной строки вырезаются (`src/restart.ts`); без файла сессии (режим `--no-session`) ничего не добавляется.
- Не сделано: флаги выбора сессии, записанные в `backend.args` личного Config, не вырезаются. `--session` перекрывает `--continue`/`--resume`, но `--fork` там остался бы ошибкой запуска Pi.
- `/q`, `/quit`, `/exit`, `/restart` встроены в приложение (`src/lifecycle-commands.ts`), а не в Extension: команды Extension грузятся только вместе с размещённым Module. Extension с одноимённой командой — ошибка запуска. Действия `actions.quit()` / `actions.restart()` доступны Command и Module, их может вызвать будущий `/update` (тикет 04).
- Завершение Backend: `Backend.stop()` закрывает stdin и ждёт закрытия процесса; через 5 с шлёт SIGTERM, ещё через 5 с SIGKILL — только этому дочернему процессу. Stdin EOF достаточно: Pi сам вызывает `session_shutdown` и убивает инструмент, который выполнялся (проверено тестом с `sleep`). Ctrl+C работает как раньше, без ожидания Backend.
- Защита от повторного вызова проверяется в процессе тестового раннера (`test/lifecycle-commands.test.ts`, счётчик запросов выхода): процессный тест её не замечал, потому что первый `process.exit` обрывает второй вызов. Прошло ревью: оно также отметило, что если Backend не отвечает на `get_state` за 2 с, перезапуск продолжит последнюю известную сессию, а пока Backend закрывается (до 10 с), интерфейс остаётся живым без индикатора.
- Resume и Fork отдельными процессными тестами не покрыты: перезапуск читает файл сессии из `get_state`, поэтому путь тот же, что у `/new`, которая покрыта.
- Тесты: `test/lifecycle.test.ts` (процессы на pty Bun, `test/process.ts`), `test/restart.test.ts`, `test/lifecycle-commands.test.ts`. Проверка «терминал чист» игнорирует режим 2027 (grapheme clusters): OpenTUI оставляет его включённым при любом выходе, включая Ctrl+C.
- `test/autocomplete.test.ts`: тест про скрытие команды Backend теперь вводит `/o` вместо голого `/`, потому что четыре новые команды вытеснили `other` из 8 строк списка.
- Вне тикета: тест `an automatic compaction leaves the chat matching Pi's messages` (`test/polish.test.ts`) падает и на чистом `HEAD` в этом окружении («No more faux responses queued»). Окно 1660 токенов, вероятно, нужно перемерить (см. `docs/agents/testing.md`).
