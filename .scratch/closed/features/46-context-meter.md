# 46: Заполненность контекста на Bottom line

**Status:** done

**What to build:** builtin Extension `context-meter` с Module `gauge`: в правом углу Bottom line всегда видно, сколько контекстного окна текущей модели занято (`▰▰▰▱▱▱▱▱▱▱ 41k/128k`). Пока агент работает, `working` стоит прямо перед ним.

## Решения

- Место выбрано прототипом из четырёх вариантов (Bottom line, разделитель над вводом как шкала, строка подсказок, строка статуса только с 70%). Победил Bottom line. Прототип лежит в ветке `prototype/context-meter` (`builtin/context/usage-indicator.prototype.tsx`).
- Цвет один при любом заполнении (`barMuted` на Bottom line, `muted` в обычной Panel): пользователь не хочет предупреждающих цветов.
- Числа берутся у Pi через RPC `get_session_stats` (`contextUsage`), а не из Pi extension `context`: та публикует снимок только пока открыт `/context`. `PiState.contextFill` обновляется при обновлении сессии (старт, смена модели и сессии), на `message_end` ответа модели и на `compaction_end`. После компакции Pi не знает расход до следующего ответа, и счётчик показывает `?`. Без модели или окна Module скрыт.

## Критерии приёмки

- [x] Счётчик стоит последним на Bottom line и после хода совпадает с расходом, который сообщает Pi.
- [x] `working` появляется прямо перед счётчиком, а сам счётчик обновляется после каждого ответа модели внутри хода.
- [x] После компакции счётчик показывает `?`.
- [x] Цвет не зависит от заполнения.
