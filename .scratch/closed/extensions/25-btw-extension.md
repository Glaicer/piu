# 25: `/btw` — побочный вопрос в отдельном окне

**What to build:** Extension `btw` с Pi extension внутри. `/btw <вопрос>` открывает Modal и сразу задаёт вопрос модели о текущей сессии; `/btw` без текста открывает Modal с пустым полем ввода. Ответ стримится в окно, в том же окне можно задавать следующие вопросы — они продолжают ту же побочную ветку. Ничего из этого не попадает в контекст сессии.

Личный Pi extension `btw` делает это через `ctx.ui.custom()`, а в RPC это no-op, поэтому под piu `/btw` сейчас не работает. Его ценная часть — Pi-сторона: он оборачивает `streamSimple` провайдера и запоминает последний запрос основного диалога, поэтому побочный вопрос попадает в кэш промпта. Эта часть переносится в Pi extension Extension'а без изменения поведения, окно делается заново как Modal.

**Blocked by:** None (can start immediately).

**Status:** done

## Решения

- **Поток идёт через зарезервированный ключ `setStatus`** `opentui:btw/state` (JSON, как у логов субагентов): `ctx.ui.editor` — запрос-ответ, поэтому многоразовый стриминг в нём не выразить. Ключ разбирается в `PiState.btw` (`src/btw.ts`) и не попадает в строку статуса; публикуется не чаще раза в 50 мс.
- **Окно держится на цепочке `editor`-диалогов канала `btw`** (`opentui:btw/side`): пока идёт ответ и пока ждём следующий вопрос, висит один диалог; его ответ — `{v:1, question}` или `{v:1, stop:true}`, а отмена диалога закрывает окно и прерывает ответ. Так Esc во время ответа доходит до Pi, не закрывая Modal.
- **`/btw` — команда piu**: она отправляет `/btw <текст>` промптом, а Pi extension открывает окно. Команда работает и пока агент занят (Pi выполняет extension-команды сразу), а в `/` одноимённую Pi-команду скрывает команда приложения.
- **Ответ рисуется как markdown основного чата** (`builtin/chat/markdown.tsx`, `createSyntaxStyle`): заголовки, списки, `**жирный**`, inline-код и подсветка блоков кода такие же, как в чате (тикет 37). Стрим обновляет markdown на месте, законченные блоки кода заново не подсвечиваются (тикет 06).

## Критерии приёмки

- [x] Побочный вопрос отправляется с тем же префиксом, что последний запрос основного диалога (модель, сообщения, опции), плюс сообщения побочной ветки; tools и `tool_choice` такие же, как в основном запросе. Без записанного запроса (сразу после resume) префикс собирается из ветки сессии, как сейчас.
- [x] Ответ стримится в Modal по мере прихода текста и рисуется как markdown чата: inline-код и блок кода выглядят так же, как в основном чате.
- [x] Esc во время ответа прерывает его; Esc без активного ответа закрывает Modal. Закрытие Modal во время ответа прерывает запрос.
- [x] Окно прокручивается стрелками и PageUp/PageDown; при новом тексте окно держится у конца, если пользователь не прокрутил вверх.
- [x] Ни вопрос, ни ответ не появляются в сессии, в её файле и в следующих запросах основного диалога.
- [x] Побочная ветка забывается при смене сессии, переходе по дереву и компакции.
- [x] Без выбранной модели или при ошибке провайдера окно показывает понятную ошибку, а не пустоту.

## Notes

- Extension channel начинает Pi extension (Dialog `editor`) и устроен как запрос-ответ, а стриминг идёт в одну сторону много раз. Как передавать поток (зарезервированные ключи `setStatus`, как у логов субагентов, или иначе) — решить в плане тикета.
- Прочитать `docs/agents/pi-extensions.md` до начала.
- Modal выглядит как выбор модели: решение «Modal «Settings» и новые Modals» в тикете 32 (`.scratch/features/settings/issues/32-settings-modal-global-tab.md`) и `docs/agents/opentui.md`.
- Extension загружает свои `commands` и Pi extension, только если один из её Modules стоит в Placement по умолчанию. Значит, Extension нужен размещённый Module, хотя бы скрытый (`reportPresence("hidden")`), или общий prefactor, который снимает это ограничение (не заведён).
- Исходник для справки: `btw.ts` в agent dir (выключен в Pi settings).

## Comments

- Modal открывается по статусу, а не по диалогу: `/btw` без текста публикует пустое окно и сразу открывает один диалог, `/btw <вопрос>` сначала запускает поток. Заголовок Modal — `btw · <model>` (80% ширины и высоты), вопрос — строка `> …` цветом `accent`, ответ — markdown чата с одним `SyntaxStyle` на окно, поле ввода — footer-модуль с `›` и подсказками `⏎ ask` / `esc stop` / `esc close`.
- `ModalRequest.onDismiss` теперь получает причину (`"escape"` или `"outside"`) и может вернуть `false`, чтобы Modal остался открытым: так Esc во время ответа отвечает `{v:1, stop:true}` и не закрывает окно. Любое другое закрытие отменяет висящий диалог, и Pi сам прерывает поток и заканчивает ветку; если диалога ещё нет (гонка), его отменит `dismissed`, когда он придёт.
- `btw.side` добавлен в Placement по умолчанию в Panel `input` и всегда скрыт (`reportPresence("hidden")`): иначе Extension, её команда и Pi extension не загрузились бы.
- Побочная ветка и записанный запрос забываются на `session_start`, `session_tree` и `session_compact` (плюс `session_shutdown`), как в личном `btw.ts`.
- В faux Backend добавлен флаг `noModels`: в Pi 1.5 при пустом реестре провайдеров модель всё равно есть (`unknown`), поэтому проверка «без модели» видит ошибку провайдера в окне — это и есть «понятная ошибка вместо пустоты».
- Тесты: `test/btw.test.ts` (16), включая `/btw` во время хода агента. Мутации сняли зелёное: без `session_tree`/`session_compact` краснеют соответствующие проверки, без префикса `main.messages` — история и tools, без обработки `stop` — Esc, без `esc`-ветки `onDismiss` — остановка, без клавиш прокрутки — прокрутка, при отправке вопроса обычным промптом — открытие окна и изоляция сессии, без отмены диалога при закрытии кликом вне окна — закрытие во время ответа, при запрете команды во время работы агента — `/btw` при занятом агенте. Проверка закрытия ждёт новое окно повтором, а не фиксированной паузой.
- `scripts/pi-bolt-compat/run.ts` запущен: Pi-Bolt в RPC не пишет в stdout ничего кроме протокола, stderr пуст, закрытие stdin завершает процесс. Компилированного `ask_user_question` в этом agent dir нет, поэтому проверка приоритета tools ничего не доказывает. Отдельно проверена перерегистрация провайдера на настоящем Pi-Bolt: временный agent dir, faux provider и `builtin/btw/pi-extension.ts`; после основного хода `/btw hello` открыл `opentui:btw/side` и прислал `opentui:btw/state` с ответом, stderr пуст. В настоящем TUI (не RPC) вручную не проверялось.
- Ctrl+Home/Ctrl+End листают к началу и концу окна: подсказку `CTRL+End: jump to bottom` рисует Panel с `followsOutput`, и без обработки она врала бы.
- `tool_choice` едет в том же `...main.options`, что и tools; тест проверяет tools через `{tools}`, отдельной проверки `tool_choice` нет (faux model его не показывает).
- Esc при `streaming`, но без висящего диалога (Backend умер посреди ответа), закрывает Modal, а не возвращает `false` навсегда. Второй `/btw` при открытой ветке показывает Toast «already open», а не молчит.
- Заголовок `btw · <model>` — модель, которой уходят побочные вопросы; она фиксируется на окно, поэтому смена модели основного диалога его не меняет.
- `modalContentInsets` (`src/layout.tsx`) и `modalText` (`test/harness.ts`) — общий способ читать текст Modal в тестах; `scrollBoxOf` вынесен в `src/scroll.ts` и переиспользуется чатом и changelog.
- Живую проверку `## После приёмки (вручную)` делает пользователь: удалить `btw.ts` из agent dir, его строку `-extensions/btw.ts` из Pi settings (иначе два обработчика `/btw` затеняют друг друга).
