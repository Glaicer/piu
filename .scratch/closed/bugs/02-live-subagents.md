# 02: Работающие сабагенты не отображаются

**What to build:** Работающие сабагенты видны в agent Panel как отдельные карточки с идентификатором, названием задачи и текущим статусом. По клику открывается Modal с живым просмотром сообщений и вызовов инструментов выбранного сабагента, чтобы пользователь мог проверить, что тот делает, не дожидаясь итогового ответа.

**Blocked by:** None (can start immediately).

**Status:** done

**Type:** bug

## Как воспроизвести

1. Запустить сабагента и оставить его выполнять достаточно долгую задачу.
2. Пока он работает, проверить его отображение в интерфейсе.
3. Попробовать открыть просмотр его работы.

По сообщению пользователя, работающие сабагенты не отображаются, и открыть просмотр их работы нельзя. При подготовке тикета поведение не воспроизводилось.

В личной установке используется Pi extension `@chthub/pi-subagents` 0.5.0 с инструментами `subagent_enable`, `agent_spawn`, `agent_send` и `agent_stop`. Начальный сценарий проверки — запуск через `agent_spawn` в фоне, пока дочерний агент продолжает работать после возврата запускающего инструмента.

## Критерии приёмки

- [x] Запущенный сабагент появляется в agent Panel до завершения своей задачи. На карточке видны его идентификатор, название задачи и статус работы; обычная карточка уже завершившегося вызова `agent_spawn` не заменяет это отображение.
- [x] Поддерживаются фоновый и блокирующий запуск: завершение запускающего инструмента или хода родительского агента не переводит продолжающего работать сабагента в завершённое состояние.
- [x] Клик по карточке открывает Modal именно выбранного сабагента. Уже полученные сообщения и вызовы его инструментов видны сразу, а новые появляются в том же просмотре во время выполнения задачи, без повторного открытия или нового сообщения пользователя.
- [x] Просмотр можно открыть и с клавиатуры. Действуют обычные правила Modal: фокус остаётся внутри, Esc или клик снаружи закрывает просмотр и возвращает пользователя в основной интерфейс. Открытие и закрытие не останавливает сабагента и не отправляет ему сообщений.
- [x] История в просмотре прокручивается независимо от основного чата. На нижней границе новые данные продолжают прокрутку; при чтении выше по истории позиция сохраняется.
- [x] Несколько одновременно работающих сабагентов показаны отдельно, в том числе с одинаковыми названиями задач. Карточки и просмотр не смешивают их сообщения, инструменты и статусы.
- [x] По окончании задачи карточка и открытый просмотр показывают фактический итог: завершение, ошибку, остановку или ожидание следующего задания у resident-сабагента. Живой, но ожидающий сабагент не обозначается как выполняющий задачу; итоговые сведения остаются доступны без дубликатов карточки.
- [x] При переходе в другую родительскую сессию её карточки и просмотр не получают данные сабагентов предыдущей сессии.
- [x] Поддержка установленного pi-subagents работает через границу Backend и не требует Pi TUI или протокольных возможностей, существующих только в Pi-Bolt. Если источник сабагентов отсутствует, приложение работает как прежде, без пустой области и ошибок запуска.
- [x] Регрессионные проверки через кадры приложения показывают карточку до завершения управляемой задачи, открытие мышью и клавиатурой, появление следующей порции вывода в уже открытом просмотре, независимость нескольких сабагентов и итоговый статус. Данные проходят через реальную RPC-границу, а не подставляются напрямую в состояние интерфейса. Стенд изолирован от личного Pi, его credentials и реальных сабагентов.

## Comments

- Исходная spec явно исключала карточки и живые потоки сабагентов. Этот запрос расширяет scope; основная spec обновлена. Тип оставлен `bug`, как указал пользователь.
- При подготовке изучен установленный `@chthub/pi-subagents` 0.5.0. Его список создаётся только в режиме Pi TUI; просмотр использует `custom()`, а `/agents` в RPC отвечает, что нужен интерактивный TUI. Перенаправить эту команду или отобразить обычный `setWidget` недостаточно.
- Фоновый `agent_spawn` возвращает идентификатор до завершения дочерней задачи. Сообщение `subagent-notification` сообщает итог, но не заменяет источник живого вывода. Нужны фактические состояния и сообщения дочернего агента, а не выводы из длительности родительского tool call.
- Этот Pi extension работает и со stock Pi; не следует считать всех таких сабагентов возможностью только Pi-Bolt. Наличие опционального `subagent_subscribe` само по себе не доказывает, что через него доступны дочерние процессы установленного pi-subagents. Источник данных нужно проверить против установленной версии; пакет и личные настройки пользователя не изменяются.
- Для этого тикета выбран просмотр в режиме чтения. Прямой чат с сабагентом, `/continue`, кнопки остановки или повторного запуска, отдельная панель во второй колонке и общий рендеринг сообщений типа custom в объём работ не входят.
- Тикет не зависит от показа ожидающих пользовательских сообщений или закрепления фоновых shell-процессов. Стенд должен повторять существенное поведение установленного Pi extension, включая ранний возврат фонового запуска и последующие обновления дочернего агента.
- Реализация: карточки стоят в agent Panel сразу после сообщений чата (`builtin/chat/subagent-card.tsx`), общий список выбора с карточками инструментов, поэтому с клавиатуры: Shift+Tab в agent Panel, стрелки, Enter. Просмотр: `builtin/chat/subagent-view.tsx`, Modal через `moduleModal` (`followsOutput`, фокус внутри, Esc или клик снаружи закрывает). В закреплённую Panel карточки не выносились, потому что в тикете названа agent Panel; при ручной прокрутке чата вверх они уходят из виду вместе с концом чата.
- Источник данных: `builtin/chat/pi-extension.ts` внутри Backend читает последнюю запись `pi-subagents-roster` родительской сессии (идентификатор, название, статус `running`/`idle`/`done`/`failed`/`stopped`) и session-файл каждого дочернего агента по `sessionPath`, раз в 250 мс, пока кто-то работает и 3 с после каждого вызова `agent_*`; снимки идут через зарезервированные ключи `setStatus` (`src/subagents.ts`). Не использованы ни виджет и `/agents` (только Pi TUI), ни `subagent_subscribe`, ни сообщение `subagent-notification`. Формат записей скопирован из 0.5.0.
- Ограничения этого источника: Pi пишет session-файл ребёнка, когда заканчивается его первое сообщение ассистента, и затем целыми сообщениями, поэтому просмотр пуст до этого момента и не показывает частично стримящийся текст. Вызов инструмента виден после конца сообщения, где он вызван, результат после выполнения. В просмотре последние 300 записей, тексты обрезаны (4000 знаков, результаты инструментов 1000, аргументы 200). Вложенные агенты (`indent` > 0) не показаны. Карточки завершённых агентов остаются до конца сессии. После `/resume` карточки появляются только когда в сессии вызван инструмент `agent_*`, и тогда показываются статусы из сохранённого списка, включая устаревшие `running`.
- Не проверено на настоящем `@chthub/pi-subagents` и Pi-Bolt: стенд `test/fixtures/pi-extensions/subagents.ts` повторяет запись списка и session-файл по прочитанному исходнику, дочерние процессы не запускаются. Запустить вручную настоящий `agent_spawn` в фоне и открыть карточку; `scripts/pi-bolt-compat/run.ts` в песочнице падает (`EACCES`), его должен запустить пользователь.
- Побочное изменение: у Modal появился фон `theme.surface` (`src/modal.tsx`). Без него текст чата просвечивал сквозь пустые ячейки просмотра. Касается и остальных Modal.
- Для теста сессии, которую Backend заменяет сам, в `faux-backend.ts` добавлен флаг `freshSessionCommand` (команда `/fresh`).
- Тесты: `test/subagents.test.ts` (11 кадровых тестов, мутации проверены: арминг опроса на `tool_call`, `followsOutput`, статус карточки, очистка при `session_shutdown`, чужой журнал в просмотре).
