# Pi extensions and installed packages

Rules for the Pi extensions an Extension carries, the test stand-ins for installed Pi packages, and everything the app reads from those packages.

- **A duplicate tool name is a hard startup failure on Pi-Bolt** (ADR-0001). An Extension's Pi extension never reuses another tool's name. To replace a tool, register your own name and drop the old one from `event.systemPromptOptions.selectedTools` in `before_agent_start`. `pi.setActiveTools()` does not hold, because the installed rpiv package re-adds its tool in a `before_agent_start` that runs after ours. A test stand-in for an installed Pi extension must copy behaviour like that (`test/fixtures/pi-extensions/`, placed with `installedPiExtensions`), or it passes on code that fails on the real one. Before writing a stand-in for an installed Pi extension, read the real one's hooks (`pi.on(...)`): the author's installed packages are in `~/.pi/agent/npm/node_modules/` (read-only). Check with `bun scripts/pi-bolt-compat/run.ts`, a manual script that needs your real agent dir: an empty one has no compiled-in Pi extensions. Run it as soon as the Pi extension first works, not at the end of the ticket. In the sandbox it fails with `EACCES` on `~/.pi/agent/trust.json.lock`, so ask the user to run `! bun scripts/pi-bolt-compat/run.ts` and say in the ticket that it is unverified until they do.
- **An Extension's `commands` load only when one of its Modules is in the Placement.** `resolvePlacement` imports an Extension through its placed Modules, so a command-only Extension never reaches `/`. The session commands sit in `builtin/chat` for that reason.
- **Pinned background processes come from the installed `@pify/shell-background`'s sidecar files, not from Pi's RPC** (`builtin/background/`; its widget is a factory, which RPC drops). The sidecar folder name and file format are copied from version 0.7.0, so re-read `~/.pi/agent/npm/node_modules/@pify/shell-background/` when it is upgraded. The pin is enabled only by `background.processes` in the Placement; a Layout without the default `pinned` Panel gets no pin, and its bash cards say `background` instead of the job's status.
- **Subagent cards and the viewer Modal come from the installed `@chthub/pi-subagents`' own leftovers, not from its widget or `/agents`** (those are Pi TUI only; `Pi-Bolt`'s `subagent_subscribe` is not assumed). `builtin/chat/pi-extension.ts` reads the latest `pi-subagents-roster` custom entry of the parent session and each child's session file (its `sessionPath`), and pushes snapshots through reserved `setStatus` keys (`src/subagents.ts`). Both formats are copied from version 0.5.0, so re-read `~/.pi/agent/npm/node_modules/@chthub/pi-subagents/` (`roster-state.ts`, `roster.ts`) when it is upgraded. Pi writes a child's session file only when its first assistant message ends and then one whole message at a time, so the viewer shows nothing until then and no half-streamed text. That Pi extension, like the session commands, loads only while `chat.messages` is in the Placement.
